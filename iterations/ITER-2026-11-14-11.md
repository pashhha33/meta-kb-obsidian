## Сделано

**`src/core/chapter.ts` (чистая логика, 10 тестов):**

| функция | правило |
|---|---|
| `defaultChapterTitle(position)` | C-CH-02: `Глава - N` |
| `resolveChapterTitle({position, requested, existing})` | C-CH-06: явное имя заменяет, пропущенное сохраняет существующее, иначе умолчание |
| `findChapter(records, book, position)` | C-CH-05: поиск по «книга + номер» |
| `chaptersOf(records, book)` | C-CH-05: порядок книги = сортировка по номеру, дырки допустимы |
| `nextFreePosition(records, book)` | следующий номер для новой главы (минимум 1) |
| `neighbourPosition(current, direction)` | C-CH-03: ±1, у первой главы «назад» нет |
| `bookLinkpathOf` / `positionOf` / `linkpathOf` | разбор значений без падений на мусоре |
| `booksForPicker` / `bookLabel` | выбор книги для диалога |

**UI:**

- `ui/modals/ChapterModal.ts` — книга (список книг хранилища), номер
  (целое ≥ 1, по умолчанию следующий свободный), имя (можно пропустить).
  Если глава с таким «книга + номер» уже есть, диалог **не** считает это
  ошибкой: показывает «Глава №N уже есть: „…“. Имя сохранится, если не
  вводить своё» — это обновление по C-CH-06.
- режим «только имя» для соседней главы (C-CH-04): книга и номер вычислены,
  пользователь вводит лишь название.

**Команды (и группа «Глава» в окне команд):**

- **Создать главу** — C-CH-01;
- **Предыдущая глава** / **Следующая глава** — C-CH-03/04: если глава с таким
  номером есть, открываем её; если нет — диалог только с именем, затем
  создание и переход;
- **Открыть книгу главы** — C-CH-03, «↑ Книга».

**Поведение, важное для пользователя:**

- глава всегда принадлежит книге: если книг в хранилище нет, команда
  объясняет это, а не создаёт главу-сироту (C-CH-05);
- существующая глава при том же номере — обновление, а не дубль; явное имя
  заменяет `title` и `aliases[0]`, `updated_at` двигается;
- вход в команду учитывает контекст: если открыта глава, диалог подставляет её
  книгу и следующий свободный номер.

## Решения

1. **Правила — в core, диалог — только ввод.** Умолчание имени, поиск главы и
   соседние номера проверяются тестами без Obsidian; `ChapterModal` не содержит
   ни одного правила C-CH.
2. **«Уже существует» — не ошибка.** Диалог не блокирует OK: по C-CH-06 это
   штатное обновление. Блокируются только невозможные состояния (нет книги,
   номер не целый или < 1).
3. **Дырки в нумерации не заполняются.** Новая глава получает `max + 1`, а не
   первый свободный номер: так номер последней главы остаётся «концом книги»,
   как описано в C-CH-05.
4. **Навигация — командами, а не кнопками в шапке.** Кнопки «← / → / ↑» в
   виджете — следующий мелкий срез; команды уже доступны из палитры и окна
   команд, и на них можно повесить горячие клавиши.

## Не вошло (следующий срез)

- **C-CH-08...C-CH-11 — объём.** `char-count` главы считается
  (`computeCharCount`), но `char-count` книги как **сумма глав** и
  `author-sheets`, а также авто-пересчёт при сохранении главы — не сделаны.
- **Кнопки навигации в шапке виджета** («← Предыдущая / Книга / Следующая →»).
- **Иконки находок в строках полей** (долг из Validation).
- **C-IMG-03** (hover-иконки) и **C-IMG-02** (колонка в Bases).
