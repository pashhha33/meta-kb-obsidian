## Сделано

**Миниатюры**

- Квадрат по умолчанию: `aspect-ratio: 1 / 1` вместо фиксированной высоты 64 px,
  из-за которой картинка обрезалась в узкую полосу.
- Настройки плагина: **«Размер миниатюр»** (48–320 px, по умолчанию 120) и
  **«Пропорции миниатюр»** (Квадрат 1:1 / Как в файле / 4:3 / 16:9).
- `core/thumbnails.ts` — `clampThumbnailSize`, `normalizeThumbnailAspect`,
  `thumbnailAspectRatio`. Настройки нормализуются и при загрузке, поэтому
  правка `data.json` руками не ломает вёрстку.
- Ширина модалки выбора изображения увеличена до 640 px, сетка — ровные
  квадратные ячейки, у `native` — сохранение исходных пропорций.

**C-IMG-01 — embed показывает изображение**

- `registerMarkdownPostProcessor`: embed `![[image_{id}]]` заменяется на само
  изображение из `attachment` (через `getResourcePath`).
- Если файл вложения не найден — в теле появляется явное сообщение, а не пустое
  место. Если `attachment` не изображение — embed остаётся как был.

**C-IMG-07 — удаление обёртки**

- Команда `Delete image wrapper` (доступна только для обёртки) и пункт
  «Meta KB: удалить обёртку…» в контекстном меню файла.
- Диалог с обязательным выбором: **«Только обёртку»** / **«Обёртку и файл»** /
  «Отмена». Файл удаляется только по явному выбору.
- Если на файл ссылается больше одной обёртки (нарушение C-IMG-05), диалог
  предупреждает об этом.
- Удаление идёт через `fileManager.trashFile`, то есть уважает настройку
  Obsidian «удалять в системную корзину».

**Тесты:** +4 (thumbnails); всего 109. Контракт: 12 настроек, schemaVersion 1.3.0.

## Принятые решения

1. **Пропорции — настройка, а не константа.** Квадрат удобен для сетки, но для
   скриншотов и схем искажение вредно; поэтому выбор отдан пользователю, а
   квадрат остался значением по умолчанию.
2. **Размер — в пикселях, с ограничением 48–320.** Ниже 48 миниатюра
   бесполезна, выше 320 сетка перестаёт быть сеткой.
3. **C-IMG-03 (hover-иконки) отложен.** Он требует интеграции с редактором
   Obsidian в Live Preview и не проверяется без живой сессии — а я не могу
   открыть Obsidian. Ставить непроверяемый код в середину среза хуже, чем
   отложить его отдельно.
4. **`attachment` остаётся `string`.** Путь, а не ссылка: иначе нарушился бы
   INV-23 (значение `media` указывает на обёртку, а не наоборот).

## Правки после проверки пользователем

### П-1. Embed не отображался в Live Preview

`registerMarkdownPostProcessor` работает только в Reading View, а пользователь
работает в Live Preview — там постпроцессоры не вызываются вообще.

Решение: тело обёртки теперь содержит `![[<вложение>]]`, и картинку рисует сам
Obsidian в обоих режимах. Постпроцессор оставлен вторым путём для `![[image_id]]`.
Тело синхронизируется при смене `attachment`; пустые тела дополняются один раз
за сессию (`backfillWrapperBodies`, с уведомлением). Текст владельца не
перезаписывается: только пустое тело или тело-embed (`shouldSyncBody`).

### П-2. Миниатюры оставались узкими полосами

Первая попытка (`flex: none` на галерее) не помогла, и это было диагностично:
высота приходила не от flex. Миниатюра — это `<button>`, а Obsidian глобально
задаёт `button { height: var(--input-height); white-space: nowrap }` и
`button:not(.clickable-icon) { background-color: …; box-shadow: … }`.

То есть картинка с `aspect-ratio: 1/1` зажималась в ~30px и обрезалась нашим же
`overflow: hidden`. Плюс `button:not(.clickable-icon)` имеет специфичность
(0,1,1) и перебивал `.meta-kb-thumb` (0,1,0) по фону и тени.

Решение: селектор `.meta-kb-gallery .meta-kb-thumb` (0,2,0) с явным
`height: auto`, `white-space: normal`, `background-color`, `box-shadow: none`.
Тот же дефект был у `.meta-kb-icon-button` (✎) и `.meta-kb-suggest-item` —
исправлен так же.

**Вывод в процесс (G3b):** появился `plugin/tests/styles.test.ts`. Он читает
`styles.css` и `src`, находит все классы, которые плагин вешает на `<button>`,
и требует для каждого `height`, `background-color` и селектор специфичнее
одиночного класса. Проверка фальсифицирована: на CSS из `610c64b` падают все
четыре её теста, на исправленном — проходят.

### П-3. Отсечка уже обёрнутых изображений при создании обёртки

Было: галерея показывала **все** изображения, а обёрнутые лишь гасила (opacity
0.6) и помечала «обёрнуто». Это расходилось с C-IMG-04 п.2, где источник —
«не обёрнутые изображения в vault».

Стало: занятые файлы в галерею не попадают вообще; если свободных не осталось,
уведомление говорит об этом вместо открытия пустого диалога. Ручной ввод пути
к занятому файлу по-прежнему даёт ошибку с предложением открыть существующую
обёртку (C-IMG-05) — то есть отсечка не ослабляет инвариант, а убирает мусор
из сетки.

### П-4. Галерея миниатюр для всех свойств с изображениями

Было: миниатюрами выбирался только `attachment` (и создание обёртки), а
`media` / `list<media>` (`cover`, `poster`, `photo`, `artwork`) открывали
текстовый поиск по названиям.

Стало: `MediaPickerModal` — галерея по `plugin/DESIGN.md` §4–5. Показывает два
вида пунктов:

- существующие обёртки `image` — выбор сразу даёт каноническую ссылку (INV-23);
- свободные изображения с пометкой «создать обёртку» — при подтверждении
  обёртка создаётся на месте (`ensureImageWrapper`), в поле пишется
  `[[image_{id}|Title]]`.

`artwork` (`list<media>`) — множественный выбор. Порядок «сначала обёртки,
потом файлы» закреплён тестом `core/media.ts`.

**Удалён `ui/modals/types/MediaModal.ts`.** После маршрутизации в
`openFieldEditor` он стал недостижим (единственный вызов `openFieldModal` идёт
только для не-media полей). Два разных UI для одного свойства — источник
расхождений, поэтому старый текстовый вариант убран, а ветка `media` в фабрике
`FieldModal.ts` возвращает `null` с комментарием, куда переехало поведение.

**Проверка контракта (G3b):** тест `контракт: cover/poster/photo — media,
artwork — list<media>` читает `resolveField` и падает, если контракт отдаст
другой `value_type`: иначе свойство молча открылось бы как текст.
