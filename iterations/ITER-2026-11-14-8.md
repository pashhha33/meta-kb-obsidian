**Статус:** completed

## Цель

Слой Validation, первый срез: **движок правил** по контракту и первое
подключение к интерфейсу.

Правила были зафиксированы с самого начала — `validationRules` в
`schema/metamodel.json` (23 штуки), проза в `metamodel/validation.md` — но
плагин их не применял: `tools/accept.mjs` проверял только фикстуры, а живое
хранилище не проверялось вообще.

## Сделано

**`src/core/validation.ts` (чистая логика):**

- `validateVault(records)` → `{ findings, errors, warnings }`, находка =
  `{ rule_key, severity, objectId, path, field?, message }`;
- `findingsForPath(result, path)` и `hasErrors(findings)` — выборки для UI;
- порядок находок стабилен (по файлу, затем по `rule_key`), чтобы отчёт не
  «прыгал» между запусками.

Реализовано **9 правил из 23** — все, что проверяются по одному объекту и
Registry, без обхода графа определений:

| rule_key | severity | норма |
|---|---|---|
| `unique-id` | error | INV-02 |
| `filename-matches-object` | error | INV-05, INV-06 |
| `aliases-first-equals-title` | error | INV-08 |
| `image-has-attachment` | error | INV-24, C-IMG |
| `image-attachment-unique` | error | C-IMG-05 |
| `link-target-exists` | error | INV-15 |
| `media-target-is-image` | error | INV-23 |
| `inactive-field-value` | warning | INV-27 |
| `deprecated-link-target` | warning | INV-10 |

**UI (минимальное подключение):**

- бейдж в шапке виджета: число находок у открытой заметки, иконка
  `alert-circle` для ошибок и `alert-triangle` для предупреждений, полный
  текст правил — в подсказке.

**Тесты (+15, всего 152):**

чистый vault не даёт находок; каждое правило срабатывает на своём случае и не
срабатывает на корректном; `deprecated-link-target` даёт warning, а не error;
пустой `title` не нарушает INV-08; порядок находок стабилен; `findingsForPath`
и `hasErrors` выбирают по объекту.

## Найденный дефект

Тест на `image-attachment-unique` поймал ошибку: пути сравнивались «как есть»,
поэтому `./img/a.png` и `img/a.png` считались разными файлами, и дубль
проходил проверку. Исправлено: сравнение через `normalizeAttachmentPath` —
ту же нормализацию, что использует индекс вложений.

## Решения

1. **Одна реализация правил — `core/validation.ts`.** `tools/accept.mjs`
   остаётся проверкой *ожиданий* на фикстурах («файл `broken_*` обязан дать
   находку») и новыми правилами не расширяется: две реализации одного правила
   разошлись бы. Переключение `accept.mjs` на собранный плагин — отдельная
   задача, записана в `metamodel/gaps.md`.
2. **Находка не удаляет и не правит данные.** `validation.md`: «данные не
   удаляются»; валидатор только сообщает.
3. **`inactive-field-value` различает два случая** в тексте: известное
   свойство, не применимое к типу, и вовсе незнакомый ключ. Пользователю это
   разные подсказки.
4. **Бейдж считает `validateVault` по всему Registry при отрисовке.** Для
   личного хранилища (сотни заметок) это доли миллисекунды; инкрементальная
   валидация — преждевременная оптимизация.
5. **Срез разделён на два.** Здесь — движок и бейдж; полный отчёт по
   хранилищу (модалка), иконки в строках полей и оставшиеся 14 правил — следующий
   срез. Иначе дифф вышел бы далеко за предел размера итерации.

## Не вошло (следующий срез)

  `trigger-values-subset`, `expansion-keys-exist`, `relation-acyclic`,
  `relation-endpoints-match`, `relation-cardinality-form`,

  находок по файлам.
- **Иконки в строках полей:** сейчас находка видна только в шапке виджета.
