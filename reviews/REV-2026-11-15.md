### P0-1. `Registry.all()` выбрасывает объекты без `id` и склеивает дубли

`core/registry.ts`:

```ts
add(rec) { if (rec.id) this.byId.set(rec.id, rec); this.byPath.set(rec.path, rec); }
all()    { return [...this.byId.values()]; }   // ← только byId
```

Следствия:
1. Заметка **без `id`** не попадает в `all()` → правило `unique-id` («у объекта
   нет id») в плагине **не может сработать никогда**.
2. Два объекта с **одинаковым `id`** — в `byId` остаётся один → вторая ветвь
   `unique-id` («встречается 2 раза») тоже мертва.
3. Все потребители `all()` (17 вызовов) не видят такие объекты: находки виджета,
   suggest, карточки, навигация по главам, индекс вложений, пересчёт книги.
   Форма виджета при этом рисуется — она читает frontmatter файла напрямую,
   поэтому пользователь видит поля, но не видит ошибку.

**Доказательство** (изолированная проба, 3 записи → `all()` = 1):

```
записей подано: 3 | registry.all(): 1 | registry.size: 1
напрямую (как в G4):        unique-id/note_no-id, unique-id/note_dup,
                            unique-id/chapter_dup, filename-matches-object/chapter_dup
через Registry (как в плагине): filename-matches-object/chapter_dup
```

**Почему ворота зелёные:** `tools/accept.mjs` строит записи сам из файлов и
вызывает `validateVault(records)`, минуя `Registry`. G4 проверяет правила, но не
тот путь, по которому данные идут в плагине.

**Исправление (срез S1):** `all()` возвращает все записи (`byPath`), `byId`
остаётся индексом для поиска; добавить тест «запись без id видна в all()» и
«два объекта с одним id дают две записи»; в `accept.mjs` собирать записи через
`Registry` — тогда G4 начнёт ловить этот класс дефектов.

### P0-2. Таймеры пересчёта книги живут после выгрузки плагина

`main.ts:426` `onunload()` гасит `rebuildTimer`, снимает hover-слой и CSS-класс,

`updated_at` уже выгруженным плагином.

**Исправление (срез S1):** в `onunload` пройти по `bookVolumeTimers`,
`clearTimeout` каждый, очистить карту. Тест — на уровне выделяемой логики
таймеров либо проверка через заглушку `window` в бандле.

### P1-1. `severity` — вторая правда в коде

Контракт задаёт `severity` для 26 правил, но `validation.ts` передаёт литералы
`"error"` / `"warning"` прямо в `finding()` (35 + 7 вхождений). Контракт в этой
части декоративен.

**Доказательство:** мутация `unique-id: error → warning` в
`schema/metamodel.json` + полный `check-all.mjs` с пересборкой → **All gates OK**,
приёмка по-прежнему рапортует `error ... unique-id`. Причина вдвойне: код не
читает severity, а `accept.mjs` сверяет только `rule_key`, не severity.

**Исправление (срез S2):** `finding()` берёт severity из контракта по
`rule_key` (фолбэк — ошибка контракта, а не молчаливый дефолт); в `accept.mjs`
ожидание проверяет и severity; тест «severity каждой находки = severity контракта».

### P1-2. `metamodel.schema.json` — мёртвый файл

На него ссылается `$schema` в контракте и WORKFLOW §2, но ни один инструмент его
не читает: `schema-check.mjs` — ручные проверки. Следствие: обязательность полей,
типы и запрет лишних ключей не проверяются (см. §4: `drop-property-label`,
`bad-required-value`, `unknown-extra-key` — MISSED).

**Исправление (срез S2):** валидировать контракт по JSON Schema в G2 (минимальный
валидатор без зависимостей либо `ajv` в devDependencies), либо честно удалить
файл и убрать обещание «структура схемы» из README. Первый вариант предпочтительнее.

### P1-4. Семантика зашита в код вопреки правилу «никаких заглушек вместо данных»

`validation.ts`: `MACHINE_KEYS` (585), `ACYCLIC_RELATIONS` (854),

### P1-5. G2 сверяет ключи, но не значения

Сверка с прозой — только наличие ключа в таблице. Меняются `label`, `required`,

не так.

**Исправление (срез S2):** сверять значения полей, которые проза действительно
фиксирует (`required`, `cardinality`, `value_type`, `extends`); защитные проверки
типа перед обходом массивов.

### P1-6. Приёмка G4 положительно проверяет 5 правил из 26

`accept.mjs` подаёт `body: ""` (171) и `imagePaths: []` (175) → правила про
главы, объём, вложения-сироты, уникальность attachment не проверяются вовсе.
Ожидание сверяется по `rule_key` без severity (193). Фикстур 9, из них с
ожиданиями 5.

Дополнительно: сами фикстуры не соответствуют онтологии — `id` вида `alice`,
`wp` вместо UUIDv7 (`ontology.md` §«id»), отсутствуют 6 из 9 обязательных

правил на обязательность этих свойств нет (`validation.md` «Волна 2»:
`requires_properties`). Пока это осознанный пробел, но канон приёмки закрепляет
невалидные данные как эталон.

**Исправление (срез S4):** фикстуры привести к онтологии; добавить фикстуры на
главы/объём/вложения (тела и `imagePaths` подавать по-настоящему); правило
`required-properties` — отдельным срезом с ADR, так как меняет строгость модели.

### P3. Производительность и робастность

1. **Виджет валидирует весь vault на каждую отрисовку.**
   `PropertiesView.render()` → `collectFindings()` → `validateVault(registry.all())`
   (214, 402), отрисовка по `active-leaf-change`, `file-open`, `layout-change`,
   `metadataCache.changed` с дебаунсом 100 мс. Плюс полная пересборка Registry
   по любому изменению метаданных (`main.ts:1066`, дебаунс 300 мс). На хранилище
   в тысячи заметок это заметно; на десятках тысяч — больно. Нужны кэш находок
   с инвалидацией по файлу и инкрементальный Registry.
2. **`resolveLink` разрешает чужой тип.** Фолбэк `linkpath.endsWith("_" + id)`
   (`registry.ts:35`): проба `resolveLink("book_dup")` вернула запись
   `chapter_dup` (тип `note`). Ссылка на книгу молча указывает на другой объект.
   Нужно сверять префикс типа.
3. **Одноимённые файлы.** `Registry.byPath` и `fileByBasename` keyed по
   `basename`; Obsidian допускает одинаковые имена в разных папках. Коллизия →
   виджет и пересчёт объёма могут работать с чужим файлом (в т.ч. писать в него).
4. **`updated_at` книги пишется всегда.** `refreshBookVolume` (`main.ts:800`)
   пишет `char-count`, `author-sheets`, `updated_at` без сравнения с прежними
   значениями, тогда как `core/derived.ts` объявляет эти ключи незначимыми для
   `updated_at`. ADR-004 п.5 требует обновлять метку при манипуляции с главой —
   противоречие стоит закрыть явно (ADR-уточнение), а не оставлять два толкования.
5. **Дубль в журнале:** «плагин загружен» пишется дважды (`main.ts:228` и `423`).
6. **Мобильные.** `isDesktopOnly: false`, но путь импорта из буфера опирается на
   `window.require("electron")` и `fs` (`main.ts:1401+`). Фолбэк на
   `navigator.clipboard` есть, ошибки логируются — падения нет, но команда
   на мобильном просто ничего не делает. Нужен `Platform.isMobile` и явное
   сообщение, либо `isDesktopOnly: true` (решение владельца).

## 4. Проверка ворот на прочность (мутации контракта)
