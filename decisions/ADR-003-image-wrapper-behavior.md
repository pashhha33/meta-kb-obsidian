# ADR-003: Поведение обёртки image

**Статус:** accepted  
**Дата:** 2026-11-04  
**Итерация:** ITER-2026-11-04-1  
**Контекст:** DISCOVERY поверх REFERENCE/

## Контекст

Reference фиксирует, что `image` — обёртка над файлом (INV-23, INV-24):  
`attachment` обязателен, сам файл не является объектом модели.  

Требуется определить конкретное поведение в теле заметки, при наведении, при создании, при удалении, роли файла и интеграцию с Bases.

## Решение

Принять правила C-IMG-01…C-IMG-07:

- Embed обёртки (`![[image_{id}]]`) показывает само изображение из `attachment`.
- Bases различает запрос метаданных и запрос изображения.
- Hover над изображением → «Открыть обёртку» или «Создать обёртку».
- Создание обёртки — с запросом имени и выбором источника (миниатюры необёрнутых файлов / буфер обмена / путь).
- **Один файл = одна обёртка** (жёсткий запрет дублей).
- Роли файла хранятся мультивыборным свойством `roles` на обёртке.
- При удалении обёртки — обязательный запрос: удалять привязанный файл или нет.

### Набор ролей (`roles`)

| Значение        | Label        |
|-----------------|--------------|
| `cover`         | Обложка      |
| `poster`        | Постер       |
| `logo`          | Логотип      |
| `illustration`  | Иллюстрация  |
| `art`           | Арт          |
| `photo`         | Фотография   |
| `icon`          | Иконка       |
| `thumbnail`     | Миниатюра    |

## Последствия

### Плюсы
- Предсказуемое поведение
- Переиспользование одного изображения
- Чёткое разделение «файл» / «объект модели»
- Роли не размножают объекты

### Риски
- Нужна надёжная индексация «файл → обёртка»
- Hover-overlay требует интеграции с редактором Obsidian
- При удалении файла нужно корректно очищать ссылки `media`
