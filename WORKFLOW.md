# Рабочий процесс v2

Как ведётся работа над метамоделью и плагином. Версия 2 заменила схему, в
которой артефакты переносились между чатом, агентом и репозиторием вручную.

## 1. Что изменилось по сравнению с v1

| Было (v1) | Стало (v2) |
|---|---|
| Чат только читает, ничего не пишет | Агент пишет файлы и собирает плагин сам |
| Агент реализует в песочнице, пользователь копирует вручную | Агент коммитит в ветку, пользователь смотрит diff и мержит |
| Приёмка — отчёт агента («✅ готово») | Приёмка — вывод команд ворот (G1–G4) |
| Состояние в `PHASE.md` «на глаз» | `check-state` проверяет согласованность |
| Метамодель как проза, код со своими заглушками | Машинный контракт `schema/metamodel.json` — единственный вход для кода |

Ручной перенос (`sandbox/`) сохраняется только для моделей без доступа к диску
(веб-чаты). Для них `sandbox/` содержит патчи и отчёт, но **не** дублирует код.

## 2. Три контура

```
A. Семантика (проза)      metamodel/*.md, decisions/*.md
        │  «что означает и почему»
        ▼
B. Контракт (машина)      schema/metamodel.json + metamodel.schema.json
        │  «что именно отдаём коду»
        ▼
C. Код и приёмка          plugin/, fixtures/vault/, tests/
        │  «что реально работает»
```

- **A** отвечает за смысл. Меняется человеком и агентом, ревью — человеком.
- **B** — единственный источник данных для плагина. Правится вручную (вариант C):
  проза задаёт смысл, схема задаёт данные, `schema-check` сверяет оба направления.
- **C** читает контракт. Заглушек вместо данных в коде быть не должно: если
  плагину нужны определения, он берёт их из B; если B нет — задача итерации не
  «сделать UI», а «сделать контракт».

## 3. Роли

| Роль | Кто | Права |
|---|---|---|
| **Владелец решений** | пользователь | утверждает ADR, мержит ветку, принимает в vault, выбирает приоритет |
| **Реализатор** | ИИ-агент | ветка итерации, правка файлов, прогон ворот, коммиты в ветку |
| **Ревьюер** | отдельная сессия агента | читает diff и инварианты, ищет нарушения; не видел рассуждений реализатора |

Независимый ревьюер заменяет самооценку: отчёт агента «всё сделано» не является
доказательством.

## 4. Ворота

Итерация не закрывается, пока не пройдены все ворота. Отчёт — **вывод команд**,
а не галочки.

```bash
node tools/check-all.mjs
```

| Ворота | Что проверяют | Файл |
|---|---|---|
| **G1** состояние | `PHASE.md` согласован с `iterations/`, следующий шаг не пуст | `tools/check-state.mjs` |
| **G2** контракт | структура схемы, уникальность ключей, целостность ссылок (extends, FE-триггеры, enum), сверка с прозой в обе стороны | `tools/schema-check.mjs` |
| **G2b** версия | `manifest.json` и `package.json` совпадают, версия в формате `MAJOR.MINOR.PATCH`, `package-lock.json` не отстал | `tools/check-version.mjs` |
| **G3a** сборка | `tsc --strict` + esbuild | `plugin/` → `npm run build` |
| **G3b** тесты | чистая логика (`core/*`) через `node:test` | `plugin/` → `npm test` |
| **G3c** загрузка | собранный `main.js` **реально загружается** и экспортирует класс плагина | `plugin/` → `npm run check:bundle` |
| **G4** приёмка | фикстуры ведут себя как задумано (валидные чисты, `broken_*` дают находку) | `tools/accept.mjs` |

**Почему G3c обязателен.** `tsc` и esbuild не ловят циклические импорты, при
которых класс наследует `undefined`: бандл собирается без ошибок, но падает в
Obsidian при включении (`Class extends value undefined`). Такая ошибка была
допущена в ITER-2026-11-06-0 и не обнаруживалась до ручной проверки.

## 5. Цикл итерации

1. **Выбор.** Одна запись из `metamodel/gaps.md` или из `PHASE.md`
   («Следующее действие»). Одна итерация — один срез.
2. **Решение.** Если меняется смысл — ADR в `decisions/` **до** кода: контекст,
   решение, последствия, что отменяет.
3. **Спецификация.** `iterations/ITER-YYYY-MM-DD-N.md`: цель, файлы, критерии
   приёмки в проверяемой форме.
4. **Реализация.** Ветка `iter-YYYY-MM-DD-N`. Проза, контракт и код правятся в
   одной итерации — иначе G2 упадёт, и это правильно.
5. **Ворота.** `node tools/check-all.mjs`. Любой красный — итерация не закрыта.
6. **Ревью.** Пользователь смотрит `git diff main...<ветка>`. Замечания — правки
   в той же ветке, не новая итерация.
7. **Фиксация.** Merge в `main`. `PHASE.md` и `metamodel/changelog.md` обновлены
   **в ветке итерации**, чтобы состояние не могло отстать. Версия плагина
   поднимается там же (см. §8 п.7).

**Версии.** `0.MINOR.PATCH`: новый срез с возможностями — `MINOR+1` (0.2.0 →
0.3.0), только исправления — `PATCH+1`. Версия правится в `plugin/manifest.json`
и `plugin/package.json` одновременно; G2b не даст им разойтись.

**Размер.** Дифф итерации — примерно до 300 строк, один вертикальный срез.
Больше — режется: сначала контракт, потом чтение контракта, потом UI.

## 6. Ветки и коммиты

- `main` — принятое состояние; сюда попадает только прошедшее ворота.
  Сообщения: `feat(...)`, `fix(...)`, `docs(...)`.
- `iter-YYYY-MM-DD-N` — срез итерации.
- Рабочие ветки процесса — `docs/...`, `workflow-v2`.

## 7. Структура

```
.github/                 (нет) — репозиторий ведётся локально + origin
metamodel/               A: проза метамодели (12 файлов)
schema/                  B: metamodel.json, metamodel.schema.json, VERSION
plugin/                  C: код плагина
  src/core/                чистая логика без импортов obsidian (тестируемая)
  src/ui/                  слой Obsidian (view, модалки, настройки)
  tests/                   node:test
fixtures/vault/          C: тестовое хранилище для приёмки
tools/                   ворота и утилиты
decisions/               ADR
iterations/              журнал итераций
REFERENCE/               исходный справочник (только чтение)
```

## 8. Правила против дрейфа

1. **Один канон.** Этот репозиторий — единственный. Прочие каталоги помечены
   `DEPRECATED.md`.
2. **Одна дверь для семантики.** Изменение смысла = ADR + changelog + bump схемы
   + закрытая запись `gaps.md` — в одной итерации.
3. **Никаких заглушек вместо данных.** Определения — из контракта.
4. **Состояние обновляет тот, кто сделал работу**, в ветке итерации.
5. **Vault знает свою ревизию.** `tools/install-vault.mjs` пишет `installed.json`
   с версией и git-ревизией рядом с плагином в хранилище.
6. **Не верить «собирается»** — проверять «загружается» (G3c).
7. **Версия не застревает.** Каждая итерация, которая ставится в хранилище,
   поднимает версию плагина: `0.2.0` → `0.3.0` для среза с возможностями,
   `0.2.1` для исправлений. Причина правила: версия оставалась `0.1.0` шесть
   итераций подряд, потому что её правили «когда вспомнят», а установка в vault
   приносила старый номер. Теперь это ворота G2b, а не память.
