# Constraints & Invariants

> Статус: в разработке (DISCOVERY)  
> Источник: REFERENCE + принятые ADR

## Поведение: Chapter (глава)

### C-CH-01. Простое создание / обновление главы

При операции «Создать главу» (или создании соседней) плагин запрашивает:

| Поле                 | Обязательность | Правило |
|----------------------|----------------|---------|
| Книга (`chapter-of`) | обязательна    | существующий `book` |
| Номер (`position`)   | обязателен     | целое число ≥ 1 |
| Имя (`title`)        | необязательно  | см. C-CH-02 и C-CH-06 |

Дырки в нумерации разрешены. Можно создать главу с любым свободным `position`.

### C-CH-02. Умолчание имени при создании

Если главы с таким `position` ещё нет и пользователь пропустил имя:

```
title = "Глава - " + position
aliases[0] = title
```

### C-CH-06. Поведение при уже существующей главе (тот же book + position)

| Ввод имени пользователем | Результат |
|--------------------------|-----------|
| Имя введено явно         | `title` и `aliases[0]` **заменяются** на введённое |
| Имя пропущено            | Существующее имя **сохраняется без изменений** |

Операция в этом случае является обновлением, а не созданием дубля.

### C-CH-03. Навигация внутри главы

В интерфейсе главы доступны:

| Действие           | Поведение |
|--------------------|-----------|
| ← Предыдущая глава | `position = current - 1`. Если нет — предложить создать (C-CH-04). |
| → Следующая глава  | `position = current + 1`. Если нет — предложить создать (C-CH-04). |
| ↑ Книга            | Переход к объекту `chapter-of`. |

### C-CH-04. Создание / открытие соседней главы

1. Вычисляется целевой `position`.
2. Если глава уже есть → просто переход на неё.
3. Если главы нет → запрос только имени (можно пропустить) → создание по C-CH-01/C-CH-02 → переход.

### C-CH-05. Инварианты

- В рамках одной книги `position` уникален (две главы с одним номером — ошибка валидации).
- `chapter-of` обязателен, кардинальность 1..1.
- `position` обязателен, целое ≥ 1.
- Порядок глав книги = сортировка по `position` (дыры допустимы).

## Поведение: Image (обёртка)

### C-IMG-01. Отображение обёртки в теле заметки

При вставке `![[image_{id}]]` (или канонического embed)  
на месте встраивания отображается **само изображение** из `attachment`, а не карточка объекта.

### C-IMG-02. Интеграция с Bases / запросами метаданных

| Запрос                         | Ответ плагина                          |
|--------------------------------|----------------------------------------|
| Метаданные объекта `image`     | Свойства frontmatter                   |
| Изображение / превью           | Файл, указанный в `attachment`         |

### C-IMG-03. Hover-поведение над изображением в теле заметки

| Состояние изображения              | Действие при наведении                          |
|------------------------------------|-------------------------------------------------|
| Уже есть обёртка с этим `attachment` | Иконка «Открыть обёртку» → переход к объекту   |
| Обёртки нет                        | Иконка «Создать обёртку» → запуск C-IMG-04     |

### C-IMG-04. Создание обёртки

1. Запрос **имени** (`title`).
2. Выбор **источника изображения**:
   - Не обёрнутые изображения в vault → выбор **миниатюрами**
   - Изображение из буфера обмена
   - Путь к изображению (диск / сеть)
3. Создаётся объект `image` с обязательным `attachment`.
4. Если для выбранного файла обёртка уже существует — создание запрещено, предлагается существующая обёртка.

### C-IMG-05. Инварианты

- `attachment` обязателен (INV-24).
- Значение `media` / `list<media>` всегда указывает на объект `image` (INV-23).
- **Один файл → максимум одна обёртка** (жёсткий инвариант).  
  Попытка создать вторую обёртку на тот же `attachment` — ошибка; предлагается существующая.
- Файл-вложение никогда не становится самостоятельным объектом модели.

### C-IMG-06. Роли изображения

Разные роли одного файла **не** выражаются несколькими обёртками.  
Роли хранятся свойством с мультивыбором на обёртке:

| Ключ   | value_type  | Значения enum |
|--------|-------------|---------------|
| `roles`| `list<enum>`| `cover`, `poster`, `logo`, `illustration`, `art`, `photo`, `icon`, `thumbnail` |


| Значение        | Label        |
|-----------------|--------------|
| `cover`         | Обложка      |
| `poster`        | Постер       |
| `logo`          | Логотип      |
| `illustration`  | Иллюстрация  |
| `art`           | Арт          |
| `photo`         | Фотография   |
| `icon`          | Иконка       |
| `thumbnail`     | Миниатюра    |

- Мультивыбор разрешён.
- Пустой список допустим.
- Набор значений расширяется только через изменение метамодели.

### C-IMG-07. Удаление обёртки

При удалении объекта `image` плагин **всегда** задаёт вопрос:

> Удалить также привязанный файл?

| Ответ пользователя | Действие                                      |
|--------------------|-----------------------------------------------|
| Да                 | Удаляется объект `image` + файл `attachment`  |
| Нет                | Удаляется только объект `image`, файл остаётся в vault |

После удаления обёртки все ссылки `media` / `list<media>`, указывавшие на неё, становятся пустыми (обрабатываются валидатором `link-target-exists`).
