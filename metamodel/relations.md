## 1. Общие правила

Отношение — объект `type: relation` (слой `system`).

- Значение хранится **в объекте-источнике**, в frontmatter под ключом `relation_key`.
- Форма значения — каноническая ссылка (INV-15) или список таких ссылок.
- Обратные направления **не хранятся**: плагин вычисляет их и показывает как входящие связи.

### Ключи определения отношения

| Ключ | Смысл |
|------|--------|
| `relation_key` | уникален, неизменяем после `accepted` |
| `source_type` | список `type_value` (или `*` = любой тип слоя `content`) |
| `target_type` | список `type_value` (или `*`) |
| `cardinality` | `0..1` \| `1..1` \| `0..*` \| `1..*` |
| `inverse_key` | только если обратная связь хранится явно (в реестре ядра не используется) |

Область (`source_type` / `target_type`) наследуется по `extends` типов.

### Форма значения по кратности

| Кратность | Хранение |
|-----------|----------|
| `0..1`, `1..1` | одиночная ссылка (не список) |
| `0..*`, `1..*` | ссылка или список |
| `1..1`, `1..*` | значение обязательно |

Отдельный `value_type` у отношения не задаётся: форма выводится из кратности.

## 2. Отношения классификации (4)

| Ключ | Label | Источник | Цель | Кратность |
|------|-------|----------|------|-----------|
| `parent` | Родительская категория | `category` | `category` | 0..1 |
| `category-domain` | Домен категории | `category` | `domain` | 1..1 |
| `object-category` | Категория объекта | любой `content` | `category` | 0..\* |
| `object-facet-value` | Значение фасета | любой `content` | `facet-value` | 0..\* |

> **ADR-001:** везде `category` вместо `hierarchical-category`.

**Правила**

- У корня дерева `parent` отсутствует.
- Циклы по `parent` запрещены.
- Все узлы одной ветки принадлежат **одному** домену (`category-domain`).
- Отдельного отношения «объект → домен» нет: домен выводится через категории объекта.

## 4. Правила семантики

1. **`part-of` и `blocks`** — ацикличны.
2. **`contradicts`** — симметрично: хранится только у источника, показывается в обе стороны.
3. **`derived-from` ≠ `references`**:  
   - `derived-from` — знание *получено* из цели (цитата из главы/книги);  
   - `references` — простое упоминание.
4. **Принадлежность главе и коллекции** хранится **со стороны элемента** (`chapter-of`, `part-of-collection`). Книга и коллекция список элементов не хранят. Порядок — свойством `position` у элемента.
5. **Приоритет частных отношений:** если для пары типов есть `chapter-of` или `part-of-collection`, общий `part-of` для этой пары **не** используется.
6. Связи с людьми — **отношениями**, не свойствами (`narrator`, `author`, `participant`…).
7. Отношения вне реестра (`answers`, `owns`, `precedes`…) пользователь создаёт как объекты `type: relation`.
8. Отношение ядра можно перевести в `deprecated`: существующие значения в заметках остаются, новые связи плагин не предлагает.

## 5. Связь с поведениями

| Отношение | Поведение |
|-----------|-----------|
| `chapter-of` | C-CH-01…11: создание главы, навигация, объём книги, уникальность `position` |
| `part-of-collection` | элемент → коллекция; порядок через `position` |
| `parent` | дерево `category`; ацикличность |

При создании объекта из пустой ссылки в ключе с единственной допустимой целью тип подставляется без вопроса (`chapter-of` → `chapter`, `narrator` → `person`) — см. Reference §15.5 и C-CH.
