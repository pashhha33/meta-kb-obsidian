## 1. Встроенные метатипы (10)

Точки замыкания самоописания.  
У всех: `type: type`, `layer: system`, `status: accepted`.  
`aliases[0]` = английский `title`, `aliases[1]` = русское имя.  
`id` фиксированы навсегда — на них ссылается `defined_by` объектов соответствующего вида.

| № | `type_value` | Русское имя | Определяет объекты слоя | Фиксированный `id` |
|---|--------------|-------------|-------------------------|---------------------|
| 1 | `type` | Тип | system | `01a17d3b-4a00-747f-b063-cd02895e0d4f` |
| 2 | `property` | Свойство | system | `01a17d3b-4a01-73dd-8782-259a7e45663f` |
| 3 | `relation` | Отношение | system | `01a17d3b-4a02-7576-a16a-764c758b99be` |
| 4 | `automation` | Автоматизация | system | `01a17d3b-4a03-7afb-a20c-42cc54509281` |
| 5 | `validation-rule` | Правило валидации | system | `01a17d3b-4a04-7c70-99cd-5c01dddac8b4` |
| 6 | `domain` | Домен | classification | `01a17d3b-4a05-7b2a-a236-1d80c3f98974` |
| 7 | `category` | Категория | classification | `01a17d3b-4a06-7991-b54e-9352cde369c0` |
| 8 | `facet` | Фасет | classification | `01a17d3b-4a07-7494-b6d9-328c7108a3c0` |
| 9 | `facet-value` | Значение фасета | classification | `01a17d3b-4a08-7875-996d-c4af6179a249` |
| 10 | `field-expansion` | Правило развёртывания полей | system | `01a17d3b-4a32-716d-82a6-503fe47a47a1` |

> **ADR-001:** `hierarchical-category` → `category` (тот же `id`).  
> `type_prefix` = `type_value` (специальный случай `hierarchical-cat` снят).

**Правила реестра метатипов**

- не удаляются, не переименовываются, не переводятся в `deprecated`;
- не участвуют в наследовании (`extends`) ни как родитель, ни как потомок;
- новый метатип — только через ADR / decision log;
- пользовательские типы и типы ядра в этот реестр **не** входят;
- при bootstrap хранилища создаются десять заметок метатипов.

**`automation`** — зарезервирован, в v1 не наполняется (нет ключей и схемы).

## 2. Типы значений (`value_type`)

Закрытый набор из **14** значений. Новое значение — только через ADR.  
После `accepted` у определения свойства `value_type` неизменяем (INV-21).  
Вложенных структур (`object`, `json`) нет.

| `value_type` | Хранение в frontmatter | Примечание |
|--------------|------------------------|------------|
| `string` | строка | короткое значение |
| `text` | строка или блочный скаляр | многострочный текст без разметки модели |
| `number` | число | без единиц в значении |
| `boolean` | `true` / `false` | |
| `date` | ISO 8601, без времени | `2026-11-05` |
| `datetime` | ISO 8601 с временем и offset | используется для `created_at` / `updated_at` (UTC) |
| `enum` | строка из `enum_values` | одиночный выбор |
| `list<string>` | список строк | |
| `list<enum>` | список строк из `enum_values` | мультивыбор |
| `link` | каноническая ссылка (INV-15) | кратность 0..1 / 1..1 |
| `list<link>` | список канонических ссылок | кратность 0..\* / 1..\* |
| `uuid` | сырая строка UUIDv7 | только машинные связи (`defined_by`) |
| `media` | каноническая ссылка на `image` | не путь к файлу (INV-23) |
| `list<media>` | список ссылок на `image` | галерея |

## 3. Типы ядра (29) — слой `content`

Стартовый набор для наполнения.  
Определения — обычные объекты `type: type` **без** фиксированных `id` (выдаются при создании).  
`type_value` после `accepted` не меняется.  
`title` (= label) — русский; `aliases[1]` = `type_value`.  
Группы ниже — только разметка реестра; в данных группа не хранится.  
Bootstrap ядра **необязателен**: можно создать только нужные типы.

Все типы ядра поддерживают отношения классификации `object-category` и `object-facet-value`.

### 3.1. Знания (корень — `note`)

| `type_value` | Label | Наследует | Назначение |
|--------------|-------|-----------|------------|
| `note` | Заметка | — | атомарная запись; `about`, `part-of`, `derived-from`, `references`, `supports` |
| `concept` | Понятие | `note` | определение термина или идеи |
| `claim` | Утверждение | `note` | тезис; `contradicts`, `supports`, `derived-from` |
| `question` | Вопрос | `note` | открытый вопрос |
| `quote` | Цитата | `note` | дословный фрагмент; `derived-from`, `author`, `about` |

### 3.2. Контекст (корни)

| `type_value` | Label | Назначение |
|--------------|-------|------------|
| `person` | Человек | автор, участник, контакт; `member-of`, `located-in` |
| `organization` | Организация | `member-of`, `located-in`, `part-of` |
| `place` | Место | `located-in`, `part-of` |
| `event` | Событие | `participant`, `located-in`, `part-of` |
| `project` | Проект | работа с результатом и сроком; `part-of`, `participant`, `blocks` |
| `area` | Область ответственности | длительная сфера без срока; `part-of`, `about` |

### 3.3. Медиа

| `type_value` | Label | Наследует | Назначение |
|--------------|-------|-----------|------------|
| `source` | Источник | — | внешний источник знания; `author`, `about`, `references`, `narrator` |
| `book` | Книга | `source` | см. роли ниже; объём — C-CH-09 |
| `article` | Статья | `source` | публикация |
| `video` | Видео | `source` | видеозапись, лекция |
| `link` | Ссылка | `source` | внешний ресурс как источник |
| `film` | Фильм | `source` | фильм / сериал / эпизод; элемент `film-series` |
| `track` | Трек | `source` | композиция, подкаст-выпуск; элемент `album` |
| `chapter` | Глава | `source` | часть книги; `chapter-of` 1..1; поведение C-CH-\* |
| `file` | Файл | — | локальный файл хранилища; корень цепочки файлов |
| `image` | Изображение | `file` | **обёртка** над файлом; поведение C-IMG-\* |

**Связи `film` / `video`:**

| Отношение | Смысл |
|-----------|--------|
| `director` | режиссёр(ы) → `person` |
| `actor` | актёр(ы) → `person` |

**Свойства `film` (дополнение к ядру):**

| Ключ | Label | value_type | required | Примечание |
|------|-------|------------|----------|------------|
| `box-office-domestic` | Внутренние сборы | `number` | нет | домашний рынок |
| `box-office-worldwide` | Мировые сборы | `number` | нет | мировые сборы |

Единица/валюта в значении не кодируется; интерпретация — соглашение пользователя (обычно USD).

**Роли `book`** (вычисляются по данным, отдельного поля нет):

| Роль | Состав |
|------|--------|
| Карточка | метаданные (`title`, `author`, …) |
| Карточка + файл | метаданные + `attachment` |
| Агрегатор глав | метаданные + входящие `chapter-of` (порядок по `position`) |

Роли не исключают друг друга. Книга-агрегатор **не** коллекция.

**Обёртка `image`:** см. ADR-003 / C-IMG-01…07.  
`attachment` обязателен; файл сам по себе не объект модели; `roles: list<enum>`.

### 3.4. Коллекции

Элементы связываются **со стороны элемента** через `part-of-collection`.

| `type_value` | Label | Типичные элементы |
|--------------|-------|-------------------|
| `film-series` | Серия фильмов | `film` |
| `album` | Альбом | `track` |
| `gallery` | Галерея | `image` |

### 3.5. Действия

| `type_value` | Label | Наследует | Назначение |
|--------------|-------|-----------|------------|
| `task` | Задача | — | действие; `part-of`, `participant`, `blocks` |
| `habit` | Привычка | `task` | регулярная практика |
| `goal` | Цель | — | желаемый результат; `supports`, `blocks` |
| `decision` | Решение | — | принятый выбор; `supports`, `derived-from`, `contradicts` |
| `meeting` | Встреча | `event` | совместное событие с участниками |

### 3.6. Сводка наследования

- 15 корней, 14 потомков;
- цепочки: `note`, `source`, `file`, `event`, `task`;
- максимальная глубина наследования в ядре — 2;
- `extends` 0..1, линейно, ациклично (общие правила — в constraints / relations).
