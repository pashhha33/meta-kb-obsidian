# Ontology (ядро метамодели)

> Статус: draft (DISCOVERY)  
> Источник: REFERENCE (Second Brain PKB, iter-015) + ADR-001…005  
> Язык ключей и идентификаторов: английский ASCII  
> Язык `title` / отображаемых имён: русский

---

## 1. Назначение

Метамодель описывает **личную базу знаний** как самоопределяющуюся объектную модель, реализованную поверх Obsidian.

- Каждая заметка (`.md`) — один **объект**.
- Данные объекта лежат в YAML frontmatter.
- Тип, свойство, отношение, правило валидации, развёртывание полей и автоматизация **сами являются объектами** с `id` и `type`.
- Предметные типы (Person, Book, Chapter…) не зашиты в код плагина: они добавляются заметками.

Плагин читает и поддерживает эту метамодель: создаёт объекты, нормализует ссылки, валидирует, считает производные поля, обеспечивает навигацию и представления.

---

## 2. Принципы

1. **Самоопределение** — всё значимое имеет `id` и `type`.
2. **Расширяемость без правки плагина** — новый тип / свойство / отношение / правило = новая заметка.
3. **Явная семантика** — у каждого объекта есть слой (`layer`) и статус (`status`).
4. **Проверяемость** — ограничения формулируются как инварианты и объекты `validation-rule`.
5. **Формализуемость для Obsidian** — типы заметок, frontmatter, wikilinks, команды, views.

---

## 3. Три слоя

| Слой | Код | Назначение | Кто создаёт |
|------|-----|------------|-------------|
| Системный | `system` | как устроена модель | автор модели / bootstrap |
| Классификация | `classification` | как объекты группируются | автор модели |
| Наполнение | `content` | знания пользователя | пользователь |

### 3.1. System

Объекты, описывающие саму модель:

- метатипы и определения типов (`type`)
- определения свойств (`property`)
- определения отношений (`relation`)
- правила валидации (`validation-rule`)
- правила развёртывания полей (`field-expansion`)
- автоматизации (`automation`) — зарезервировано, в v1 не наполняется

### 3.2. Classification

Три независимых механизма группировки:

| Механизм | Тип объекта | Смысл |
|----------|-------------|--------|
| Domain | `domain` | крупная предметная область верхнего уровня (не иерархичен) |
| Category | `category` | узел дерева внутри домена (иерархия через `parent`) |
| Facet | `facet` + `facet-value` | независимое измерение; значения равноправны |

Привязка знания к классификации — отношениями `object-category` и `object-facet-value`.  
Домен объекта **вычисляется** из доменов его категорий и отдельно не хранится.

> **ADR-001:** бывший `hierarchical-category` переименован в `category`.

### 3.3. Content

Экземпляры типов ядра (note, book, chapter, person…) и пользовательских типов.  
Именно здесь хранятся знания.

**Правило согласования (INV-09):** `layer` — явное свойство; расхождение `layer` и `type` — ошибка данных.

## 4. Идентичность объекта

### 4.1. Обязательные свойства (9)

У **любого** объекта на **любом** слое:

| Ключ | value_type | Правило |
|------|------------|---------|
| `id` | `uuid` | UUIDv7, строчная каноническая форма (36 символов); уникален во всём vault; **неизменяем** |
| `type` | `string` | ASCII kebab-case; после `accepted` менять не рекомендуется |
| `defined_by` | `uuid` | сырой UUID определения типа в слое `system` (`type: type`), чей `type_value` = `type` объекта; **не wikilink** |
| `title` | `string` | непустой; читаемое имя; изменяем; не обязан быть уникальным |
| `aliases` | `list<string>` | не меньше одного; `aliases[0]` **всегда** = `title` |
| `layer` | `enum` | `system` \| `classification` \| `content`; согласован с `type` |
| `status` | `enum` | `draft` \| `accepted` \| `deprecated` |
| `created_at` | `datetime` | ISO 8601; **хранится в UTC**; задаётся при создании; **неизменяемо** |
| `updated_at` | `datetime` | ISO 8601; **хранится в UTC**; обновляется при каждом значимом изменении |

> **ADR-004:** добавлены `created_at` / `updated_at`.  
> **ADR-005:** `owner` исключён из обязательных (в Reference был INV-11).

**Отображение времени** — настройка плагина `datetimeDisplay`:  
`local` (по умолчанию) | `utc` | `fixed-offset`.

#### Роль `defined_by`

Машинная привязка экземпляра к **прямому** определению его типа (объект `type: type` в `system`).

- Плагин по `defined_by` загружает схему типа (поля, `extends`, excludes, field-expansion).
- Указывает на прямое определение, не на предка по `extends`.
- Хранится как **сырой UUID** (не каноническая ссылка): стабильность при смене `title`/имени файла, детерминированная валидация, замыкание самоописания метатипа `type` на себя.

### 4.2. Имя файла

```
{type_prefix}_{id}.md
```

- `type_prefix` **вычисляется** из `type` (не задаётся вручную).
- Путь (папка) **не** часть идентичности.
- Переименование файла нужно только при смене `type`.

Алгоритм `type_prefix` (из Reference DL-009):

1. lower-case;
2. разделители (пробел, `_`, `.`, `/`) → один `-`;
3. удалить всё, кроме `[a-z0-9-]`;
4. убрать `-` по краям;
5. если длиннее 16 символов — обрезать до 16 и убрать конечный `-`;
6. пустой результат → объект невалиден.

> Специальный случай `hierarchical-cat` **удалён** вместе с переименованием в `category` (ADR-001).

### 4.3. Каноническая ссылка (INV-15)

```
[[{type_prefix}_{id}|{title}]]
```

- Ссылки без alias, по одному `title` или с путём — **неканонические**; плагин нормализует их.
- Исключение: `defined_by` хранится как **сырой UUID** (не wikilink).

### 4.4. Пустое значение

Пустое значение свойства = **отсутствие ключа** в frontmatter.  
Не пустая строка, не `null`, не `[]` (для списков отсутствие = нет ключа).

## 5. Статусы жизненного цикла

| Статус | Смысл |
|--------|--------|
| `draft` | свободная правка; экземпляры черновых типов не основа автоматизаций; правила в `draft` не применяются |
| `accepted` | стабильно; действуют ограничения на смену ключевых полей определений |
| `deprecated` | выведен из эксплуатации, но сохранён; ссылки остаются действительными; новые объекты по нему не создаются; обратимо |

Встроенные метатипы в `deprecated` **не** переводятся.

---

## 6. Самоописание

- Определение типа — объект `type: type`, `layer: system`.
- У него есть `type_value` — строка, равная `type` всех его экземпляров.
- `defined_by` экземпляра указывает на `id` этого определения.
- Метатип `type` замыкается на себя: `defined_by` равен собственному `id` (единственная допустимая самоотсылка).

Внешний реестр «типов типов» не нужен.

## 8. Границы v1

**Входит:**
- три слоя, 10 метатипов (с `category`), 9 обязательных свойств;
- идентичность, канонические ссылки, статусы;
- поведения chapter и image (см. constraints);
- timestamps и объём book/chapter.

**Не входит в первую версию онтологии (отложено):**
- свойство `owner` (ADR-005);
- наполнение `automation`;
- формальный язык условий validation-rule;
- переопределение унаследованных полей (Q-003);
- триггеры по фасетам (Q-008);
- детальная модель ролей `book` / format (Q-007).
